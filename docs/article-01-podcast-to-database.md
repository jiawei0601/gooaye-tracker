# 我把 682 集《股癌》變成資料庫，然後發現他在航海王那年一次都沒看多過

> 六年語料、50,790 個檢索塊、總建置成本 US$5.5——以及我一路上搞砸的地方。

> **數據截止**：本文所有統計截至 2026-07-25（EP682）。這個專案每週三/六自動更新，
> 最新數字請看[儀表板](https://jiawei0601.github.io/gooaye-tracker/data/dashboard.html)。
> RAG 索引涵蓋 EP1–EP682（結構化層）／EP1–EP680（逐字稿層，粉絲站出稿有時間差）。

---

## 一、先講那個發現

2021 年，台灣股市只有一個主角：航運。

那年最誇張的時候，航運族群佔台股單日成交量三成以上。長榮、陽明、萬海被叫成「航海王」，
連沒在看盤的人都在群組裡討論。

我把《股癌》從 2020 年開播到現在的 682 集全部跑成結構化資料之後，
查了一下他對「航運」這個族群講過什麼。結果是這樣：

```
航運：38 次提及（2020-08 → 2026-03）

立場分佈    觀察 24  |  中性 8  |  看空 6  |  看多 0
逐年提及    2020: 1   2021: 22   2022: 10   2023: 3   2024: 0   2025: 1   2026: 1
```

**38 次提及，一次「看多」都沒有。**

而且這不是事後諸葛。時間軸完整記錄了他當下講的話——包括他的猶豫、他的承認錯過、
以及他坦白自己看不懂：

| 集數 / 日期 | 立場 | 當集觀點 |
|---|---|---|
| EP125 / 2021-03-24 | 中性 | 運價上漲為短期現象，反轉通常快速，不具長期成長性，追高風險大 |
| EP135 / 2021-04-28 | 觀察 | 近期漲幅驚人，但因風險考量未重押，**認為錯過也屬正常** |
| EP147 / 2021-06-09 | 觀察 | 航運族群佔台股交易量三成以上，是**罕見的世界奇觀**，但屬於藝高人膽大的標的 |
| EP149 / 2021-06-16 | 觀察 | **主持人未跟到貨櫃輪行情** |
| EP151 / 2021-06-23 | 觀察 | 二、三十年一遇的行情，但**坦言看不懂終點** |
| EP161 / 2021-07-28 | **看空** | 台灣以電子立國，航運難以成為主流，貨櫃輪長期不賺錢 |
| EP184 / 2021-10-16 | **看空** | 景氣循環股，無新常態，產能開出後終將歸於平淡 |
| EP250 / 2022-06-04 | 觀察 | 台股融資餘額三成在航運，若斷頭潮未出現可能影響市場結構 |

然後 2023 年剩三次，**2024 年整年零提及**。族群退燒，就不再談了。

我對這個結果的感想不是「他好神」——他自己就說了沒跟到，錯過一段二、三十年一遇的行情。
真正讓我覺得有意思的是：**一個人在群眾最狂熱的時候的完整態度軌跡，居然可以這樣被攤開來看。**

這種東西你用聽的聽不出來。你只會記得「他好像沒很愛航運」，但記不得他是哪一集開始這樣講、
中間有沒有動搖過、什麼時候才真正轉成看空。

要看見這個，得先把六年的音訊變成可以查詢的東西。這篇文章講的就是這件事怎麼做的，
花了多少錢，以及我在過程中搞砸了什麼。

## 二、為什麼做這個：我脫節了

動機其實有點難為情：**我有好幾年沒認真聽了。**

中間工作忙、生活有事，就這樣斷掉。等到想回來的時候，發現一個很現實的問題——
我不是想知道「最新一集講什麼」，我是想知道**「這幾年他對各個族群的看法變成怎樣了」**。

這兩個需求差很多。前者只要聽最新的幾集就好；後者代表我得補回好幾百集。

而且我要的是族群層級，不是單集摘要。「他現在怎麼看記憶體」這種問題，
答案散落在幾十集裡面，每次講一點，立場還會變。單集摘要幫不上忙，
我需要的是**跨年度的立場軌跡**。

這個需求直接決定了後面所有的技術選擇：

- 因為要跨年度 → 必須做全歷史回填，不能只處理新集數
- 因為要族群層級 → 分析輸出必須結構化到「產業 × 立場 × 論點」，不能只是一段摘要
- 因為要看得出變化 → 得把同一個族群的所有提及串成時間軸

有趣的是，**做完之後才看得見的東西，恰好是我原本沒想到要找的**——
像上面那個「零看多」，還有下面這個。

## 三、第二個發現：資料也會暴露「沒說的話」

同樣的邏輯套在個股上。我查了 PLTR（Palantir），它在六年間被提到 50 次：

```
2020:  5  █████
2021:  9  █████████
2022:  0            ← 整年零提及
2023:  1  █
2024:  8  ████████
2025: 14  ██████████████
2026: 13  █████████████
```

**最大空窗 574 天**（2021-11-24 → 2023-06-21）。

而 2022 年正是 PLTR 股價一路走跌、離 2021 年初高點愈來愈遠的那一年。

我不打算把這個講成陰謀論——空窗也可能只是我的抽取管線在那段時間漏了。
但它示範了一件事：**結構化之後，「沒有發生的事」也變成可觀察的資料。**
你聽節目不會注意到某檔股票消失了兩年，因為缺席本來就沒有聲音。

（這裡我只放 2020-2022 的歷史立場。這個專案不提供任何近期的多空判斷，
原因在文末的邊界那一節。）

## 四、管線：為什麼跳過「轉錄再摘要」

技術上第一個要決定的事，是怎麼把 50 分鐘的音訊變成結構化資料。
直覺做法是兩段式：先轉逐字稿，再叫 LLM 摘要。我最後沒這樣做。

當初評估過四條路：

| 方案 | 為什麼不用 |
|---|---|
| YouTube 字幕 | 頻道已關閉字幕（用 yt-dlp 和 youtube-transcript-api 雙重確認過），不通 |
| NotebookLM | 沒有公開 API，要自動化只能模擬瀏覽器，脆弱且違反服務條款；而它底層本來就是 Gemini |
| 本機 whisper | 8GB CPU 筆電跑一集要 30 分鐘，光回填 26 集就是 13 小時，而且還需要第二段 LLM |
| **Gemini 音訊理解** | 一步輸出結構化 JSON；免費層 250 req/day、250k TPM，一集音訊約 10 萬 token |

最後選了第四條：下載 mp3 → 上傳 Gemini Files API → 直接輸出
包含摘要、產業立場、個股立場的 JSON。

**我想強調的是「跳過中間步驟」這件事本身。**
兩段式管線多出來的不只是時間，還有一次資訊損失（語氣、停頓、強調都在轉錄時丟掉了）
和一個額外的失敗點。當模型本身吃得下音訊，中間那層就是純粹的成本。

歷史回填則走另一條路——後來發現有粉絲網站把 678 集逐字稿整理好，
而且是用單一檔案打包（給前端搜尋用的），一個請求就能全拿。
於是原本規劃的「綁定計費、衝刺轉寫 518 集」方案，直接作廢。

這件事的教訓很俗但很真：**動手做苦工之前，先花 30 分鐘找有沒有現成的資料源。**

## 五、RAG 的兩個設計原則

分析資料之外，我把全歷史逐字稿也建成了一個本機 RAG 索引，
最後是 50,790 個檢索塊，裝在一個 456MB 的 SQLite 單檔裡。

這部分有兩個決定我覺得值得講。

### 原則一：原文絕對不經過 LLM

切塊的時候，逐字稿**原文直接進庫**，不先摘要、不先改寫。
LLM 只負責產出另一層可過濾的結構化資料（立場、分類、標的）。

很多 RAG 實作會讓 LLM 先把文件摘要一遍再入庫，理由通常是省 token。
但這樣做的後果是：**你檢索到的永遠是模型的轉述**。一旦模型理解錯了，
錯誤會被永久固化進知識庫，而且你沒有任何辦法察覺——因為原文已經不在了。

所以我的庫裡永遠有一份未經轉述的一手內容。LLM 產出的東西是**附加層**，
不是替代品。

### 原則二：混合檢索不是為了炫技

我一開始也懷疑純向量或純關鍵字是不是就夠了。後來實測讓我死心。

我在庫裡做了個統計。假設一個台灣使用者想查「他對輝達的看法」，
第一直覺一定是打「輝達」兩個字：

| 統計 | 塊數 |
|---|---|
| 搜「**輝達**」命中 | **729** |
| 實際在談這家公司（含各種說法） | **2,461** |
| **只用其他說法、完全沒出現「輝達」二字** | **1,732（70%）** |

他實際上是這樣講的：

| 說法 | 次數 |
|---|---|
| Nvidia（不分大小寫） | 1,559 |
| 輝達 | 729 |
| NVDA | 294 |
| **老黃** | **256** |
| 黃仁勳 | 118 |

**他用「老黃」代稱整家公司 256 次。**

> 「我個人覺得**老黃家的公司**真的是可以持續關注的」（EP63）
> 「在**老黃的 A100、H100** 被制裁的時候」（EP286）
> 「當**老黃它開這樣的東西**，看起來很差，結果 AMD 好像特別卓越」（EP269）

而沒有任何使用者會想到要去搜「老黃」。

這就是關鍵字檢索的天花板，而且它不是技術問題：**你搜不到你想不到的詞。**
語意腿的價值就在這裡——把「老黃」「黃仁勳」「NVDA」拉到向量空間的同一個區域，
你打「輝達」也撈得回來。兩腿結果再用 RRF 融合排序。

還有一個更基本的問題：關鍵字腿對自然語言長句根本無能為力。
同一個索引，`--q "CPO 共同封裝光學的看法"` 用 keyword 模式回傳**零結果**，
但 `--q "CPO"` 就正常。而真實使用者不會只打一個詞。

（另外提一個測量陷阱：我做上面那個統計時，一度想用「台積」當「台積電」的替代詞，
結果漏失率算出來只有 10%——因為「台積」是「台積電」的子字串，
所有台積電都被算進去了。**做這類統計，替代詞不能跟標準詞有子字串關係。**）

## 六、我搞砸的地方

### 免費端點跑到一半降速 40 倍

回填 678 集的時候，我用的是某個免費推論端點。前面一切順利，一集 60 到 90 秒。

然後它開始變慢。

不是掛掉——**掛掉還比較好處理**。它是慢慢地、持續地變慢，
從 60 秒變 2 分鐘，再變 5 分鐘。我盯著進度條看了很久，一直在猶豫要不要停。
因為每次它跑完一集，你就會想「說不定下一集就恢復了」。最後 ping 過去 90 秒沒回應，
我才確定不是我的問題。

剩下的 491 集切到 DeepSeek 官方 API：**7 到 12 秒一集，零失敗，總共花了大約 US$2.5。**

快了大概 40 倍，成本是兩杯手搖飲。

教訓很清楚：**免費端點適合「不趕時間」的批次，趕進度的時候付費 API 便宜到不該猶豫。**
但更實際的教訓是——你需要一個明確的放棄門檻，事先寫下來。
不然你會像我一樣，在「再等一下說不定會好」裡面耗掉好幾個小時。

### 我以為做完了，其實錯了 51 筆

這個更難受。

全部回填完、儀表板也產出來之後，我隨手拿逐字稿做了一次全庫美股代號審計。
結果修正了 **51 筆誤植，橫跨 39 集**。

錯誤有兩類。第一類還算好抓：symbol 欄位填了公司全名而不是代號，
例如 Qualcomm 直接寫成 `Qualcomm` 而不是 `QCOM`。這種一眼看得出來。

**第二類是真正可怕的。**

Lumentum 這家公司被標成了 `LUMN`。

看起來很合理對吧？Lumentum → LUMN。問題是 **LUMN 是 Lumen Technologies 的代號**——
一家完全不相關的電信公司。Lumentum 的正確代號是 `LITE`。

這個錯誤不會觸發任何格式驗證。它是四個大寫字母，符合美股代號格式，
而且**它真的存在**，你去查行情還查得到報價。下游的彙整、儀表板、切塊全部一路綠燈。
如果我沒有另外拿逐字稿做交叉比對，這 51 筆會就這樣留在庫裡。

我從這件事學到的是：**LLM 輸出的驗證不能只驗格式，要驗事實。**
而「錯得很合理」的幻覺，比「錯得很離譜」的危險一個量級——
後者會被擋下來，前者會被當成正確答案用下去。

而那個判斷，沒有 API 可以呼叫。

## 八、這個東西的限制（誠實版）

寫到這裡都是好消息，但這個資料庫有明確的問題，我覺得應該講清楚。

**1. 「觀察」這個標籤被過度使用。**
PLTR 那 50 筆裡有 21 筆標成「觀察」，但其中不少實際上是「主持人未明確表態」——
聽眾提問、或只是順口提到。嚴格說那不是立場，是「有提到」。
正確的做法應該是多一個 `未表態` 類別，把「有提到」和「有立場」分開。這是設計失誤。

**2. 立場標籤和論點內容會不一致。**
有一筆標成「已出場」，但論點寫的是「曾作為先上車的投資範例，即使短期下跌，長期仍有機會」——
這根本不是出場的理由。模型在標立場和寫論點的時候，顯然沒有互相校驗。

**3. 近期集數的抽取品質有退化。**
論點欄位的空白率，2020 到 2024 年都在 3% 以下，
但 2025 年跳到 28%、2026 年 17%。原因我還沒查清楚，但它是真的。

**4. 所有立場都是模型推論，不是本人確認。**
這點大概不用多說。

我把這些寫出來不是自我批評表演。而是**如果一個資料專案只展示它做對的部分，
你沒有辦法判斷它哪裡不能信。**上面第二點和 LUMN 那件事其實是同一個問題的兩個面向：
LLM 的輸出看起來永遠是有自信的，驗證得靠你自己做。

## 九、版權與邊界

這種爬取／衍生類的專案，「哪些不公開」的決定比「做出什麼」更重要，所以講一下我的處理：

- 節目內容著作權屬於原作者。**音訊與逐字稿全文一律不進公開 repo**，
  而且已經從 git 歷史整批清除，只留在本機供個人研究。
- 公開的資料只有 **AI 生成的轉化性摘要與立場標註**，含少量短引句。
- 儀表板上的「逐字稿」連結，在公開版是 404——**這是刻意設計，不是 bug。**
- 程式碼採 MIT，資料另有聲明。
- 若原作者對資料發佈有異議，我會立即移除。

另外，**這個專案不提供也不打算提供任何投資建議。**
文章裡的所有立場引用都停在 2022 年，就是為了避免變成傳播明牌。
它是一個資訊彙整工具，AI 分析會出錯，立場標籤是模型推論的，
不要拿它當投資依據。

## 十、想改追別的節目

管線本身是通用的。要換成別的 podcast，實際上只要改兩個地方：

1. `scripts/common.py` 裡的 `FEED_URL` 換成目標節目的 RSS
2. `scripts/analyze.py` 的 prompt 裡，把領域詞彙調整成你要的（我的版本塞滿了台股術語）

其餘的部分——集數註冊表、冪等的逐集存檔、彙整、儀表板產生、通知——都不用動。

程式碼在這裡：<https://github.com/jiawei0601/gooaye-tracker>
儀表板在這裡：<https://jiawei0601.github.io/gooaye-tracker/data/dashboard.html>

如果你也做了類似的東西，我很想看看你怎麼處理「立場」這種主觀標籤——
那是我到現在都還沒解好的部分。
